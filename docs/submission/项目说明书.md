# KnowMe 知我 · 项目说明书

> 一句话：**让 AI 从「回答问题的窗口」变成「记得住你、能替你办事的个人智能系统」。**

- 代码仓库：https://github.com/zrchen-ops/KnowMe--
- 演示分支：`knowme`（仓库首页即最新版）
- 技术栈：Expo (React Native) + TypeScript + Zustand + 零依赖 Node Agent 服务 + DeepSeek V4.1 Flash

---

## 一、我们要解决的问题

现在的 AI 产品，绝大多数仍然是这个流程：

```
打开 App → 输入问题 → 得到回答 → 关闭 App → 下次从头解释自己
```

这带来三个真实痛点：

1. **AI 不认识你**：每次对话都从零开始，用户要反复复述背景、偏好、进度。
2. **AI 只给建议，不办事**：聊得再好，计划还是用户自己记、自己排、自己跟进。
3. **AI 不理解状态变化**：连续三天没完成计划，普通 AI 只会说"你应该提高自律"，而不是结合上下文发现「这个计划本身排太满了」。

KnowMe 想验证的是另一条路径：

```
你表达目标/经历 → AI 理解并结构化 → 你确认 → 进入个人图谱与日程
→ 逐个执行 → 产生真实进度 → 阶段复盘 → 反过来更新对你的认知
```

**关键差别：AI 的输出不再是"一段话"，而是"一条可追溯、可修改、可删除的数据"。**

---

## 二、产品形态

KnowMe = 个人认知系统 + AI 伙伴 + 个人智能操作系统。三者共享同一套个人上下文。

| 模块 | 作用 | 交付形态 |
|---|---|---|
| **Agent 对话** | 语音/文字输入 → 抽取结构化记忆 → 用户确认 | 对话页 + 记忆确认卡片 |
| **我的图谱** | 以「我」为中心的个人知识图谱，节点可点、可改、可删 | SVG 力导向视图 + 节点详情 |
| **成长系统** | 目标 / 里程碑 / 周日程 / 时长统计 / 周复盘 | 目标卡 + 周视图 + 复盘页 |

三者的关系不是"三个功能"，而是**同一份数据的三种视图**：一条记忆确认后，会同时生成图谱节点、目标/任务/事件，并被统计与复盘消费。

## 三、创新点

### 1. 记忆不是聊天记录，而是"双向可追溯的结构化数据"

每条记忆都有 `type / confidence / origin / source / payload`，并挂着一个 `sourceMemoryId` 反查来源。
删除是**双向对称**的：删记忆 → 级联清节点与关系；删目标 → 连带清它的来源记忆。市面上多数"AI 记忆"只是向量库里的碎片，用户看不见也改不了。

### 2. 图谱是真实数据结构，不是画出来的装饰

`Relation` 有语义（拥有目标 / 计划 / 记录 / 认识 / 感兴趣 / 偏好 / 习惯），节点类型由记忆类型**强制映射**，不由模型自由发挥。因此同一个「组会」不会一会儿是 `plan` 一会儿是 `event`。

### 3. 模型只做"理解"，不做"决策"

模型输出被当作**草稿**：服务端逐字段校验（长度 / 日期格式 / 枚举 / 置信度），不合法的字段直接丢弃而不是写进图谱。去重、归并、建关系、算统计全部由客户端确定性代码完成 —— **同样的输入必然得到同样的图**。

### 4. 失败可降级，且明确告知用户

服务端不可用（断网 / 没配 key / 模型超时）时，客户端自动回落到本地规则引擎，并在 UI 明确提示「已用本地引擎回复」。不假装成功，也不让用户卡死。

## 四、技术架构

```
┌──────────────────────────────┐
│  Expo App (iOS / Android / Web)│
│  app/ · components/            │
│  Zustand + AsyncStorage        │
└───────────────┬───────────────┘
                │ POST /agent/respond
                │ （失败自动降级本地引擎）
┌───────────────▼───────────────┐
│  Agent 服务（server/）         │
│  · 提示词 + 上下文裁剪          │
│  · 输出归一化与校验             │
│  · DeepSeek / OpenAI 兼容端点   │
└───────────────────────────────┘
```

**技术选型理由**

| 选择 | 理由 |
|---|---|
| Expo + Expo Router | 一套代码覆盖 iOS/Android/Web，评委无需装包即可用浏览器体验 |
| Zustand + persist | 状态与持久化在同一处，本地优先，不依赖后端账号 |
| 零依赖 Node 服务 | 只有一个 `/agent/respond`，用 Node 原生 TS 执行，`npm run agent` 即起 |
| DeepSeek V4.1 Flash | 1M 上下文、支持 JSON Output，价格约为主力模型 1/4；抽取任务不需要思考链 |

**关键工程细节**

1. **thinking 默认关闭**：V4.1 Flash 默认开思考模式（慢 3–5 倍且 `temperature` 失效），抽取任务显式 `thinking: {type: 'disabled'}`。
2. **JSON Output + 解析容错**：`response_format: json_object`；端点不支持时自动去掉重试；被 ```` ```json ```` 包裹也能解析。
3. **密钥隔离**：模型调用只在服务端，客户端只拿到 `EXPO_PUBLIC_AGENT_API_URL`；上下文按需裁剪（最近 12 条记忆 + 活跃目标 + 待办 + 节点名）。
4. **一致性由测试保障**：记忆投影矩阵、级联删除、统计口径、Provider 与归一化共 39 个单测。

## 六、与同类方案的差异

| 维度 | 通用 AI 助手 | 纯笔记/图谱工具 | KnowMe |
|---|---|---|---|
| 记忆 | 会话内上下文，或黑盒向量库 | 用户手写 | 对话产生 → 用户确认 → 可追溯可编辑 |
| 图谱 | 无 | 手动连线 | 记忆投影自动生成，且可反向编辑 |
| 执行 | 只给建议 | 只记录 | 目标 → 日程 → 完成事件 → 进度回写 |
| 闭环 | 断在"回答完" | 断在"记完" | 复盘 → 下周计划 → 执行 → 再复盘 |
| 数据主权 | 平台侧 | 本地 | 本地优先，密钥只在服务端，可一键清空 |

## 七、边界与克制

我们刻意**没有**做这些（MVP 阶段）：

- ❌ 自动读取用户聊天记录 / 相册 / 其他 App 数据
- ❌ 完全自主的后台 Agent
- ❌ 付款、订票、发消息等高风险自动执行（只回应并提示确认）
- ❌ 为了"看起来智能"而高频推送

主动服务的原则写进了产品约束：**有真实上下文、有明确价值、低打扰、可关闭、用户拥有最终控制权**。

---

## 八、当前局限（如实说明）

1. 语音输入是演示占位，未接真实转写。
2. 真机渲染路径（引导跳转、启动时序）尚未做端到端验证。
3. 图谱布局为 12 个固定槽位，超过 12 个非中心节点会重叠。
4. 记忆的「过期 / 被纠正」尚无独立状态，目前只能改或删。
5. 无多端同步与数据导出。
